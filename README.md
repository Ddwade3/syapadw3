# senior-designer — плагин Claude Code для продуктового дизайна в Figma

Пакет, который превращает Claude Code в сеньор-дизайнера с процессом, правилами в цифрах, автоматической проверкой макетов в Figma и памятью решений арт-директора. Ставится один раз, работает во всех проектах.

## Что внутри

```
.claude-plugin/marketplace.json          ← репозиторий = маркетплейс с одним плагином
plugins/senior-designer/
  .claude-plugin/plugin.json
  hooks/hooks.json, hooks/session-start.sh   ← правила загружаются в КАЖДУЮ сессию автоматически
  skills/design/SKILL.md                     ← процесс: бриф → токены → референсы → 3 направления → сборка → QA → критик → показ
  skills/design/references/
    rules.md          ← контраст, размеры, отступы, сетка, кнопки, формы — в цифрах
    typography.md     ← шкалы, гарнитуры с кириллицей, пары по нишам
    patterns.md       ← современные паттерны секций и компонентов
    anti-patterns.md  ← приметы «AI-дизайна» и устаревшие приёмы
    checklist.md      ← чек-лист приёмки для критика
  skills/new-project/SKILL.md                ← /senior-designer:new-project — старт клиентского проекта
  scripts/figma-qa.js                        ← автопроверка секции в Figma: наложения, контраст, размеры, отступы, повторы, имена
  agents/design-critic.md                    ← критик со свежим контекстом, вызывается перед каждым показом
  agents/chatgpt-image.md                    ← курьер к ChatGPT за картинками (дешёвый контекст)
templates/CLAUDE.md, templates/design-notes.md ← шаблоны для папки проекта
```

## Установка (один раз, на своём компьютере)

Способ 1 — терминал (самый надёжный; в приложении Claude есть кнопка терминала, подойдёт и обычный Terminal):
```
claude plugin marketplace add Ddwade3/syapadw3
claude plugin install senior-designer@syapadw3-design
```
Плагин ставится в область «для меня» (user scope) и доступен во всех проектах — в приложении, в терминале и в VS Code, потому что они читают одни и те же настройки.

Способ 2 — попросить Claude в локальной сессии приложения выполнить эти же две команды через Bash.

Способ 3 — через интерфейс приложения: сначала зарегистрировать маркетплейс (способ 1, первая команда), затем **+ → Plugins → Add plugin**, выбрать `senior-designer`, область «для меня».

После установки — новая сессия (или `/reload-plugins`). Проверка: набрать `/` и увидеть `/senior-designer:design` и `/senior-designer:new-project`; команда `claude plugin list` показывает `senior-designer@syapadw3-design`.

Если репозиторий ещё без ветки `main`, укажите ветку явно: `claude plugin marketplace add Ddwade3/syapadw3#claude/gracious-galileo-b40ps4`.

Обновление после новых коммитов в репозитории: `claude plugin marketplace update syapadw3-design` (или `/plugin` → Marketplaces → syapadw3-design → Update marketplace). Версия в манифесте намеренно не указана: плагин следует за коммитами.

## Как работать

1. **Новый клиент** → новая папка на диске → открыть её в Claude Code как проект → `/senior-designer:new-project Автомойка Х`. Claude создаст `CLAUDE.md` и `design-notes.md`, спросит ТЗ/прототип/референсы, зафиксирует бриф, предложит токены и соберёт UI-кит в Figma.
2. **Каждый блок** → «делаем герой». Claude сам: задача блока → примеры из Mobbin → 3 направления текстом → вы выбираете → сборка на токенах → `figma-qa.js` → критик → показ с одной строкой объяснения.
3. **Правки** → «не нравится: кнопка теряется». Claude запишет причину в `design-notes.md` и больше так не сделает.
4. **Между блоками** в длинной сессии — `/clear`. Контекст проекта лежит в `CLAUDE.md`, ничего не потеряется, а лимит перестанет гореть на перечитывании истории.

Один проект = одна папка = свои сессии. Не держать три клиента в одном чате.

## Что плагин делает автоматически, а что нет

- Правила и процесс попадают в контекст каждой сессии через SessionStart-хук — их не нужно вызывать.
- Скилл `design` подключается сам на любую задачу про интерфейс (по описанию). Если хочется наверняка — начать сообщение с `/senior-designer:design`.
- Проверку в Figma (`figma-qa.js`) и критика Claude обязан запускать перед показом — это записано в правилах. Если он этого не сделал, одна фраза «ты не прошёл QA» возвращает его в процесс.
- Плагин не делает Claude безошибочным. Он убирает основные источники брака: отсутствие цифр, выдуманные паттерны, показ непроверенного, забытые решения.

## Как дополнять

- Забраковали что-то в проекте → это уже в `design-notes.md` проекта.
- Повторяется из проекта в проект → добавить строку в `plugins/senior-designer/skills/design/references/anti-patterns.md` (или `rules.md`) и закоммитить — после `Update marketplace` правило действует везде.

## Почему свой плагин, а не готовые (проверено в октябре 2026)

| Что есть на рынке | Вердикт для Figma-процесса |
|---|---|
| **frontend-design** (Anthropic, Apache-2.0) | Полезен: список примет «AI-дизайна» и процесс «план → сверка с брифом → сборка → критика». Его идеи включены в `anti-patterns.md` и в процесс; ставить отдельно не обязательно, но не мешает |
| **design** (Anthropic, knowledge-work-plugins, у тебя уже установлен) | Полезен частично: `design-critique` и `accessibility-review` — хорошие рубрики ревью, срабатывают сами при словах «оцени/проверь дизайн». Наш `design-critic` строже и привязан к нашему чек-листу |
| **figma** (плагин Figma, 14 скиллов) | Не для Bridge: все скиллы завязаны на официальный Figma MCP, лицензии нет, запись в канвас планируют сделать платной. 14 описаний скиллов занимают контекст в каждом ходу — если официальный MCP не используешь, плагин лучше выключить |
| **Impeccable** (80.9k★, Apache-2.0) | Заточен под код и браузер: критика требует детектор и DOM; при каждом новом дизайне делает сетевой запрос на impeccable.style, который нельзя отключить, и скачивает бинарник. Переносимые части (shape, typeset, layout, craft-floor) учтены в наших правилах |
| **UI UX Pro Max** (135.6k★, MIT) | База стилей/палитр/шрифтовых пар + генерация дизайн-системы по описанию продукта (Python, без сети). Можно поставить как необязательный генератор идей на шаге токенов; но стиль у нас задают бриф и референсы, поэтому по умолчанию не нужен |
| claude2figma, figma-review-skill, AccessLint, design-review (Playwright) | Привязаны к официальному Figma MCP или к коду/браузеру — с Bridge не работают |
| **awesome-design-md** (121k★, MIT) | 84 файла DESIGN.md с реальных продуктовых сайтов — хорошая библиотека направлений; можно подключать как референсы по ссылке |

## Требования

- Claude Code v2.1.29x или новее (плагины, скиллы с `when_to_use`, агенты с `effort`).
- Свой Figma-плагин Bridge (или официальный Figma MCP) — для выполнения `figma-qa.js` и сборки.
- Коннектор Mobbin в claude.ai (для примеров) — по желанию, но сильно повышает качество паттернов.
- Chrome с расширением Claude — для агента `chatgpt-image`.
